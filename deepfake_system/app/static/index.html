Detecting Facial Deepfakes in Video Using Spatial, Temporal & Spectral Evidence

A prototype forensic tool that examines a video for signs of face manipulation and produces a report an investigator can actually read. It combines MTCNN face tracking, 2D-FFT frequency analysis and audio–visual lip-sync checks, and always states how confident it is rather than giving a bare yes or no.

01

Project Overview

What the system is for, what it covers, and what it deliberately does not attempt.

Aim

Build a working detection pipeline that takes a suspect video, isolates the faces in it, scores each frame for manipulation, and outputs a hash-sealed forensic report suitable for evidential handling.

Objectives

  • Extract and align faces reliably across compressed video.
  • Fuse spatial, temporal and spectral cues into one calibrated score.
  • Report a confidence interval, not just a label.
  • Preserve chain of custody with SHA-256 hashing.

Scope

  • In scope: face swap, reenactment and synthesis in short video clips.
  • In scope: WhatsApp and messenger re-encoded footage.
  • Out of scope: full-body synthesis, still images, live streams.

Deliverables

  • Detection engine (PyTorch) behind a FastAPI service.
  • This examiner interface, with PDF report export.
  • Browser extension for in-page media checks.
  • Evaluation over 200 held-out clips.
02

How to Use the System

Four steps from an unverified clip to a report you can submit or hand over.

  1. 1

    Sign in

    Create an examiner account. Access is gated so that every examination is attributable, which is what chain-of-custody guidance expects.

  2. 2

    Submit the clip

    Drag a file into the ingestion panel, or press Load Sample Evidence Clip if you only want to see the workflow. MP4, MOV, AVI, MKV and WebM up to 250 MB.

  3. 3

    Read the verdict

    You get a score, a confidence band around it, the per-frame profile, the face crops used, and a plain-English note explaining what drove the result.

  4. 4

    Export the report

    Download a PDF holding the verdict, the file hash, container metadata and the signal breakdown, or export the raw JSON for further analysis.

Uploaded media is held in memory for the duration of the analysis and discarded immediately afterwards. Only the numeric findings and the file hash are retained, so the tool can be used on sensitive material without creating a second copy of it.

          05

          Detection Methodology

          The pipeline a submitted clip travels through, and the four analyses that feed the score.

          1. Stage 1 Decode & sample Frames drawn at a fixed interval via FFmpeg.
          2. Stage 2 Face detection MTCNN locates and aligns faces to 224×224.
          3. Stage 3 Feature extraction CNN embedding plus FFT and motion descriptors.
          4. Stage 4 Fusion & scoring Weighted combination against the calibrated threshold.
          5. Stage 5 Report Verdict, confidence band and SHA-256 seal.

          MTCNN facial alignment

          Detects and normalises the facial region in each sampled frame. Crops are standardised to 224×224 so that landmark positions and blend boundaries can be compared frame to frame.

          Zhang et al., 2016

          2D-FFT spectral profiling

          Takes a 2D Fourier transform of each face crop to look for the checkerboard and upsampling residue that transposed-convolution generators tend to leave in the high-frequency band.

          Durall et al., 2020

          Temporal motion coherence

          Compares optical flow and boundary stability between consecutive frames. Swapped faces often flicker at the mask edge or drift against the head pose in a way real faces do not.

          Inter-frame variance analysis

          Zero-retention handling

          Submitted media is buffered in temporary memory for feature extraction and unlinked as soon as scoring finishes, so no second copy of the evidence is created on disk.

          Limitations & Ethical Considerations

          Stated openly, because a detector presented without its failure modes is not much use as evidence.

          Dataset bias

          Training data is dominated by FaceForensics++ and Celeb-DF. Generators released after those datasets, and faces underrepresented in them, are likely to be scored less reliably.

          Compression sensitivity

          Heavy re-encoding removes exactly the high-frequency residue the spectral branch depends on. The messenger heuristic compensates in part, but low-bitrate footage widens the confidence band considerably.

          Not a legal determination

          The output is an investigative indicator. A score above the threshold means manipulation signatures were found, not that manipulation is proven; corroboration is still required.

          Face-dependent

          If MTCNN finds no usable face — heavy occlusion, extreme pose, very low resolution — the pipeline cannot score the clip and returns inconclusive rather than guessing.

          Adversarial pressure

          Detection and generation move together. A generator trained against a published detector can suppress the artefacts it looks for, so measured accuracy should be read as a snapshot.

          Consent and privacy

          All evaluation footage came from publicly released research datasets with their own consent terms. No personal media was collected for this project, and nothing submitted here is stored.
